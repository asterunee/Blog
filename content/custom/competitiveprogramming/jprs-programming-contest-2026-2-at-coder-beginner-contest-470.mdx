## A. Fizz

그냥 구현이다. `1`부터 `N`까지 돌면서 `i`가 `3`의 배수면 `Fizz`, 아니면 `i`를 출력하면 된다. 딱히 볼 건 없고 `i % 3 == 0`만 체크하면 끝.

복잡도는 `O(N)`.

## B. Monocolor

최종 색을 하나 정했다고 생각하면 그 색이 아닌 공들만 다시 칠하면 된다. 따라서 어떤 색 `c`를 골랐을 때 필요한 연산 수는 `N - cnt[c]`이고, 당연히 가장 많이 나온 색으로 몰아주는 게 이득이다.

즉 답은 `N - max(cnt)`다. 색별 빈도만 세면 끝이고 복잡도는 `O(N)`.

## C. Inc, Dec, Xor

1번 쿼리는 쉽다. 현재 `A[x] = v`일 때 `v -> v+1`로 바뀌므로 전체 xor 값 `ans`에서는 기존 `v`를 빼고 새 값 `v+1`을 넣으면 된다. xor는 같은 값을 두 번 xor하면 사라지므로 `ans ^= v ^ (v+1)`만 해주면 된다.

문제는 2번 쿼리다. 매번 전체 배열을 다 보면 당연히 터진다. 여기서는 현재 `A[i] > 0`인 인덱스들만 따로 들고 있으면 된다. 2번 쿼리가 오면 그 리스트만 돌면서 `A[i]`를 1 줄이고, xor 값도 `ans ^= old ^ new` 식으로 갱신한다. 감소해서 0이 된 원소는 다음 리스트에 안 넣고, 아직 양수인 애만 다시 넣는다.

처음엔 2번 쿼리마다 리스트를 긁으니까 이것도 커 보이는데, 상각으로 보면 된다. 리스트에서 원소 하나를 한 번 처리했다는 건 실제로 그 원소 값을 1 감소시켰다는 뜻이다. 그런데 감소할 수 있는 총 횟수는 결국 앞에서 1번 쿼리로 증가한 총 횟수보다 많을 수 없다. 전체 증가 횟수는 최대 `Q`번이므로, 2번 쿼리에서 리스트를 도는 전체 횟수도 최대 `Q`번이다.

결국 전체 복잡도는 `O(N + Q)`이다. 이 문제는 괜히 복잡한 lazy를 잡기보다 이 상각 관찰 하나 보는 게 핵심이다.

## D. Inverse and Swap

2번 쿼리의 조건 `P[P'_i] = i`는 그냥 `P'`가 현재 `P`의 역순열이라는 뜻이다. 따라서 현재 순열 `P`와 그 역순열 `I`를 둘 다 들고 있으면 된다.

1번 쿼리에서 위치 `x, y`를 스왑한다고 하자. 기존 값이 `a = P[x]`, `b = P[y]`였다면 `P[x], P[y]`를 바꾸고, 역순열 쪽에서도 `I[a] = y`, `I[b] = x`로 고치면 된다. 전부 `O(1)`이다.

2번 쿼리는 더 쉽다. 현재 `P`를 역순열로 바꾸면 새 순열은 기존 `I`가 되고, 그 새 순열의 역순열은 다시 기존 `P`다. 따라서 그냥 `swap(P, I)` 한 번 하면 끝이다.

모든 쿼리를 `O(1)`에 처리할 수 있어서 전체는 `O(N + Q)`.

## E. Concentration

처음 보면 카드마다 점수가 달라서 큰 값을 우선 노리는 전략이 필요해 보이는데, 실제 최적 행동은 카드 숫자 자체와 무관하다. 이미 짝을 확실히 알고 있으면 그 짝은 바로 먹는 게 항상 이득이다. 반대로 먹을 수 있는 짝이 없으면 이미 본 카드를 또 까는 것보다 새로운 정보를 얻는 쪽이 손해가 없다. 결국 전략은 카드에 적힌 실제 값이 아니라 **현재 몇 종류를 어느 상태로 알고 있는가**만 보면 된다.

그래서 먼저 최적으로 플레이했을 때 **먹는 쌍의 기대 개수**를 구하면 된다. 모든 카드 종류는 셔플 후 완전히 대칭이므로 각 종류가 먹힐 확률도 같고, 최종 점수의 기대값은

`(먹는 쌍의 기대 개수) * (A의 총합) / N`

이 된다.

이제 DP를 잡자. `f(l, a, b)`를 다음처럼 둔다.

* `l`: 남은 라이프
* `a`: 아직 두 장 다 본 적 없는 종류의 개수
* `b`: 한 장의 위치만 알고 있는 종류의 개수

이 상태에서 앞으로 먹을 수 있는 쌍 수의 기대값을 `f(l, a, b)`라고 하자.

현재 뒤집어볼 만한 미확인 카드는 총 `2a + b`장이다.

첫 번째 카드가 이미 한 장 위치를 알고 있던 종류의 짝일 확률은 `b / (2a + b)`다. 이 경우 바로 짝을 맞춰서 1쌍을 먹고 상태는 `f(l, a, b-1)`로 간다.

반대로 확률 `2a / (2a + b)`로 완전히 새로운 종류가 나온다. 그 뒤 두 번째 카드에서는 세 경우가 있다.

* 같은 종류의 다른 한 장을 뽑는다.
* 기존에 한 장 위치를 알던 종류의 짝을 뽑는다.
* 또 다른 완전 새로운 종류를 뽑는다.

각 경우마다 상태가 정해지고, 틀렸으면 라이프가 1 줄어든다. 이걸 그대로 전이식으로 적으면 된다.

베이스는 두 개다.

* `l = 0`이면 더 이상 실패를 허용 못 하므로 기대값은 0
* `a = 0`이면 남은 `b`종류는 한 장씩 이미 알고 있는 상태니까 전부 확정으로 먹을 수 있어서 값은 `b`

이렇게 라이프 작은 쪽부터 DP하면 된다. 상태 수는 `O(L N^2)`이고 각 상태 전이는 상수 개라 전체도 `O(L N^2)`이다. `N, L <= 200`이라 충분히 돈다.

마지막에 `f(L, N, 0)`을 구해서 `A` 평균을 곱하면 답이다.

## F. Googol Swaps

스왑 가능한 위치들을 정점으로 보고, 각 연산 `(A_i, B_i)`를 간선으로 보자. 그러면 같은 연결요소 안에서는 스왑들을 조합해서 문자들을 원하는 대로 섞을 수 있고, 서로 다른 연결요소 사이로 문자가 넘어가지는 못한다.

이제 연산 횟수가 정확히 `10^100`번이라는 조건을 보자. 이 수는 짝수다. 스왑 한 번은 순열 parity를 뒤집으므로, 최종적으로 가능한 위치 순열은 **각 연결요소 안에서만 움직이면서 전체 parity가 짝수인 순열**들이다.

먼저 parity를 무시하자. 어떤 연결요소 크기가 `s`이고 그 안의 문자 빈도가 `c1, c2, ...`라면, 그 연결요소 안에서 만들 수 있는 서로 다른 문자열 개수는 `s! / (c1! c2! ...)`이다. 이걸 모든 연결요소에 대해 곱하면 parity를 무시한 전체 경우의 수가 된다.

이제 parity 조건을 보자.

만약 어떤 연결요소 안에 같은 문자가 두 개 이상 있다면, 그 두 문자를 서로 바꾸는 것은 문자열은 그대로인데 순열 parity만 뒤집는다. 즉 그런 연결요소가 하나라도 있으면 어떤 최종 문자열이든 parity를 마음대로 맞출 수 있다. 따라서 이 경우에는 parity 무시한 값이 그대로 답이다.

반대로 모든 연결요소에서 문자가 전부 서로 다르면, 최종 문자열 하나가 사실상 순열 하나와 일대일 대응한다. 그러면 가능한 순열 중 정확히 절반이 짝수 순열이므로 이 경우에만 답을 2로 나누면 된다.

연결요소는 DSU로 잡고, 각 컴포넌트별로 알파벳 개수를 세서 팩토리얼/역팩으로 계산하면 된다. 전체는 사실상 선형이다.

## G. ΣШX

mex를 구간마다 직접 계산하려고 하면 당연히 답이 없다. 여기서는 mex를 누적 조건으로 바꾸는 게 핵심이다.

어떤 구간의 mex가 `m`이라는 건 그 구간에 `0, 1, ..., m-1`이 전부 들어 있다는 뜻이다. 따라서 그 구간은 `k = 0, 1, ..., m-1`에 대해 각각 한 번씩 카운트되고, 총 `m`번 세어진다.

즉 전체 mex 합은 `k = 0, 1, 2, ...`를 순서대로 보면서 **0부터 k까지를 전부 포함하는 부분배열의 개수**를 전부 더한 것과 같다.

이제 왼쪽 끝을 `l`로 고정하자. 값 `x`가 위치 `l` 이후에서 처음 등장하는 곳을 `next[x][l]`이라고 하자. 그러면 구간이 `0,1,...,k`를 모두 포함하기 위한 최소 오른쪽 끝은

`R[l] = max(next[0][l], next[1][l], ..., next[k][l])`

가 된다.

어떤 값이 뒤에 아예 없으면 그 위치를 `N+1`로 잡으면 된다. 그러면 왼쪽 끝이 `l`인 유효한 구간 개수는 `N + 1 - R[l]`개다.

이제 `k`를 하나씩 늘린다고 생각하면 기존 `R[l]`에 새 값 `next[k][l]`만 추가하면 되므로 갱신은

`R[l] = max(R[l], next[k][l])`

이 한 줄이다.

값 `k`의 등장 위치를 `p1 < p2 < ... < pc`라고 하자. 그리고 `p0 = 0`, `p(c+1) = N+1`을 붙인다. 그러면

* `l`이 `p0+1`부터 `p1`까지면 `next[k][l] = p1`
* `l`이 `p1+1`부터 `p2`까지면 `next[k][l] = p2`
* ...
* `l`이 `pc+1`부터 `N`까지면 `next[k][l] = N+1`

이 된다.

즉 값 `k` 하나를 추가할 때 필요한 갱신은 몇 개의 **구간 chmax**로 떨어진다.

따라서 배열 `R`에 대해

* 구간에 `chmax`를 하고
* 전체 합 `sum(R)`를 빠르게 구할 수 있으면

된다.

내가 잡은 방식대로면 세그비츠로 각 구간에 `R[i] = max(R[i], x)`를 박고, 루트에서 `sum(R)`를 바로 꺼내면 된다. 현재 `k`에 대해 조건을 만족하는 부분배열 개수는

`sum over l of (N + 1 - R[l])`

이고, 이건

`N * (N + 1) - sum(R)`

와 같다.

이 값을 모든 `k`에 대해 답에 더하면 전체 mex 합이 된다.

각 값의 등장 위치는 전체 합쳐서 `N`개뿐이고, 각 등장 위치로부터 만들어지는 구간 chmax들도 총량이 선형이라 세그비츠에 태우면 전체는 `O(N log N)` 정도에 된다.

핵심 흐름은 딱 이거다.

`mex 합`
`-> 0..k 전부 포함하는 구간 개수의 합`
`-> next 위치들의 max`
`-> 구간 chmax + 전체 합 관리`
