## 1. Decayed Bridges

다리를 실제로 하나씩 지우려고 하면 연결 컴포넌트가 쪼개지는 걸 관리해야 해서 귀찮은데, 순서를 뒤집어서 **다리가 하나도 없는 상태에서 역순으로 복구한다**고 보면 DSU로 바로 떨어진다. 처음에는 모든 섬이 서로 끊겨 있으므로 불편도는 $N(N-1)/2$이고, 역순으로 다리 `(a,b)`를 추가할 때 둘이 이미 같은 컴포넌트라면 아무 변화가 없다. 서로 다른 컴포넌트고 크기가 각각 $x,y$라면 지금까지 연결되지 않았던 $xy$개의 섬 쌍이 새로 연결되므로 불편도에서 $xy$만 빼주면 된다. 각 시점의 답은 해당 다리를 다시 추가하기 직전의 불편도를 저장하면 되고, 전형적인 offline reverse + DSU 문제다. 시간복잡도는 $O((N+M) alpha(N))$ 정도라 사실상 선형으로 컷난다.

## 2. Integer Product

실수 그대로 곱하면 오차 때문에 바로 터질 수 있으니 입력을 문자열로 받고 소수점 아래를 9자리까지 0으로 채운 뒤 **전부 $10^9$를 곱한 정수**로 바꾼다. 원래 수를 $X/10^9$라고 보면 두 수의 곱이 정수일 조건은 두 정수의 곱이 $10^18$의 배수인 것과 같고, $10^18$은 2가 18개, 5가 18개 곱해진 수이므로 결국 각 수에서 2와 5가 몇 번 나오는지만 보면 된다. 각 지수는 18을 넘겨도 의미가 없으니 18에서 cap하고 `(2의 지수, 5의 지수)`별 개수를 세어둔 뒤, 두 타입의 2 지수 합과 5 지수 합이 각각 18 이상인 조합만 긁으면 끝이다. 타입이 고작 19×19개라 타입 쌍은 그냥 브루트해도 되고 입력 처리까지 포함해서 사실상 $O(N)$이다.

## 3. Shuffle Permutation

두 행 `x,y`가 모든 열에서 합이 $K$ 이하라면 둘은 직접 swap할 수 있으므로 행을 정점으로 보고 이런 쌍끼리 간선을 잇는다. 연결 컴포넌트 안에서는 간선에 해당하는 swap들을 조합해서 **아무 permutation이나 만들 수 있기 때문에** 크기가 $s$인 컴포넌트의 기여는 $s!$이다. 열도 완전히 똑같이 처리하면 된다. 여기서 행을 섞으면 열 조건이 깨질 것 같지만 각 열의 원소 순서만 같이 permutation되는 것이므로 두 열을 비교했을 때 모든 행에서 합이 $K$ 이하라는 조건 자체는 그대로 유지되고, 열을 섞어도 행 조건이 똑같이 보존된다. 따라서 행 DSU와 열 DSU를 독립적으로 만든 뒤 각 컴포넌트 크기의 factorial을 전부 곱하면 끝이고, 모든 행 쌍과 열 쌍을 직접 확인하므로 시간복잡도는 $O(N^3)$이다.

## 4. Sort Arrays

각 수열은 `A[i] = A[x[i]] + [y[i]]` 꼴이라 모든 수열을 실제 vector로 만들어 비교할 필요 없이 **Trie의 노드 하나로 표현**할 수 있다. 어떤 canonical node `p`에서 값 `y`를 하나 붙인 수열은 `(p,y)`라는 쌍으로 유일하게 결정되므로 이 쌍을 hash map에 넣어 같은 수열은 같은 노드로 합친다. 같은 노드에 속한 원래 인덱스들은 입력 순서대로 `same`에 넣어두면 이미 작은 번호 순서가 되고, 각 노드의 자식은 붙인 값 `y` 기준으로 오름차순 정렬한다. 사전순에서는 어떤 수열 자체가 그 수열을 prefix로 가지는 더 긴 수열보다 먼저 나오므로 **현재 노드의 `same`을 먼저 출력하고 자식 subtree를 `y` 오름차순으로 DFS**하면 정확히 원하는 순서가 된다. 전체 Trie 크기는 최대 $N+1$이고 자식 정렬까지 포함해서 평균 $O(N log N)$ 정도로 해결된다.

## 5. Crossing Table Cloth

두 천의 합집합이 정확히 `[S,T]`가 되어야 한다고 보면 경우를 둘로 나누는 게 편하다. 먼저 `[S,T]` 자체인 천이 존재한다면 나머지 천 하나가 `[S,T]` 안에 완전히 포함되기만 하면 되므로, 같은 `[S,T]`가 두 장 이상 있거나 proper subset인 천이 하나라도 있으면 `Yes`다. `[S,T]` 자체가 없다면 왼쪽 끝 `S`를 덮기 위해 한 천은 반드시 `S`에서 시작하고, 오른쪽 끝 `T`를 덮기 위해 다른 천은 반드시 `T`에서 끝나야 한다. 그래서 `S`에서 시작하면서 `T`를 넘지 않는 천 중 오른쪽 끝이 가장 큰 값을 $R1$, `T`에서 끝나면서 `S`보다 왼쪽으로 나가지 않는 천 중 왼쪽 끝이 가장 작은 값을 $L2$라고 잡으면 된다. 둘 사이에 빈 셀이 없어야 하므로 $L2$가 $R1+1$ 이하이면 가능하고 아니면 어떤 조합을 골라도 불가능하다. 시작점별 `R`과 끝점별 `L`을 정렬해두고 이분탐색하면 각 쿼리를 $O(log M)$에 처리할 수 있다.

## 6. Bitwise OR Game

전체 pile의 XOR을 `xr`, OR을 `o`라고 하면 놀랍게도 답은 **`xr == o`인지 아닌지만 보면 된다**. `xr == o`인 상태에서 합법적인 move로 어떤 pile의 값 `x`를 더 작은 `y`로 바꾸면 OR은 규칙상 그대로인데 XOR은 `x xor y`만큼 반드시 바뀌므로 다시 `xr == o` 상태로 갈 수 없다. 반대로 `xr != o`라면 `d = xr xor o`를 잡고 `d`의 가장 높은 1비트를 가지고 있는 pile 하나를 골라 값을 `x xor d`로 바꾸면 된다. 가장 높은 비트가 1에서 0으로 내려가므로 값은 확실히 작아지고, `d`에서 1인 비트들은 전체 OR에는 있지만 XOR에는 없는 비트라 최소 두 pile 이상이 가지고 있어서 하나를 꺼도 OR은 유지된다. 그리고 새로운 XOR은 정확히 `o`가 되므로 상대에게 losing state를 넘길 수 있다. 따라서 `xr == o`면 Bob, 아니면 Alice고 전체를 한 번 긁기만 하면 돼서 $O(N)$이다.

## 7. ARC Wrecker 2

구간 안에서 인접한 두 빌딩의 높이를 동시에 1씩 올리거나 내리는 연산이므로 **alternating sum이 invariant**라는 걸 보면 바로 풀린다. 구간 `[l,r]`에 대해 `A[l] - A[l+1] + A[l+2] - ...`를 생각하면 한 번의 연산은 인접한 두 항에 같은 값을 더하거나 빼는데, 두 항의 부호가 반대라 변화량이 정확히 상쇄된다. 최종적으로 전부 0을 만들려면 이 alternating sum이 0이어야 하고, 반대로 alternating sum이 0인 구간은 필요한 인접 연산들을 적절히 구성해서 실제로 전부 0으로 만들 수 있으므로 이 조건이 필요충분이다. 이제 전체 배열의 alternating prefix sum을 만들어두면 `[l,r]`의 alternating sum이 0일 조건은 `prefix[r] = prefix[l-1]`과 동치다. 따라서 같은 prefix 값이 이전에 몇 번 등장했는지만 세면서 그 개수를 답에 더하면 끝이고, `unordered_map` 하나로 평균 $O(N)$에 컷난다.

## 8. Distribute Bunnies

토끼 하나는 점프 후 `X-R` 또는 `X+R` 둘 중 하나에만 갈 수 있으므로 **두 도착 좌표를 정점으로 하고 토끼를 그 둘을 잇는 간선으로 바꾸면** 그래프 문제가 된다. 각 간선에서 양 끝점 중 하나를 선택하는 것이 토끼의 최종 위치를 고르는 것과 같고, 목표는 선택된 서로 다른 정점 수를 최대화하는 것이다. 연결 컴포넌트에 정점이 $V$개, 간선이 $E$개 있다고 하자. 컴포넌트가 트리라면 $E=V-1$이라 간선마다 서로 다른 정점을 하나씩 잡아도 최대 $V-1$개이고, 실제로 루트를 하나 정한 뒤 각 간선에서 자식 쪽 정점을 선택하면 전부 달성할 수 있다. 반대로 사이클이 하나라도 있으면 spanning tree로 $V-1$개를 채우고 남는 간선 하나로 마지막 정점까지 잡을 수 있으므로 $V$개 전부 가능하다. 따라서 컴포넌트 하나의 기여는 그냥 `min(V,E)`이고, 모든 도착 좌표를 좌압한 뒤 DSU로 컴포넌트를 만들고 간선 수를 세면 된다. 정렬 때문에 전체 $O(N log N)$이다.

## 9. Digits Parade

왼쪽부터 숫자를 하나씩 붙여가면서 **현재까지 만든 수를 13으로 나눈 나머지**만 들고 있으면 된다. `dp[r]`를 지금까지 처리한 prefix가 나머지 `r`이 되는 경우의 수라고 두면 다음 digit이 `d`일 때 새로운 나머지는 `(10r+d) mod 13`이다. 현재 문자가 실제 숫자라면 그 digit 하나로만 전이하고, `?`라면 0부터 9까지 전부 긁어서 전이하면 된다. 처음에는 아무 숫자도 없는 상태를 나머지 0인 한 가지 경우로 두고 문자열 전체를 처리한 뒤 `dp[5]`를 출력하면 끝이다. 상태가 13개밖에 없고 `?`에서도 10개 digit만 확인하므로 시간복잡도는 $O(130N)$, 사실상 $O(N)$이다.

## 10. Extension

최종 격자의 색칠을 마지막 연산 기준으로 나누면 DP가 나온다. `dp[i][j]`를 처음 $A×B$에서 시작해서 $i×j$까지 확장했을 때 가능한 서로 다른 색칠 수라고 두자. 마지막에 위쪽에 새 행을 붙였다면 이전 상태는 `(i-1,j)`이고 새 행의 `j`개 칸 중 하나를 검게 칠할 수 있으므로 `j * dp[i-1][j]`개가 나온다. 마지막에 오른쪽 열을 붙인 경우도 똑같이 `i * dp[i][j-1]`개다. 다만 두 경우에 동시에 세어진 색칠이 있는데, 이런 색칠에서는 새 행의 검은 칸이 오른쪽 끝이 아니고 새 열의 검은 칸이 위쪽 끝이 아니어야 하므로 중복이 정확히 `(i-1)(j-1) * dp[i-1][j-1]`개 생긴다. 따라서 두 값을 더하고 이 중복만 빼주면 되고, 시작 상태 `dp[A][B]=1`에서 목표 `(C,D)`까지 긁으면 된다. 상태 수가 최대 약 900만 개라 $O((C-A+1)(D-B+1))$으로 충분하고, rolling array를 쓰면 메모리는 $O(D)$까지 줄일 수 있다.
